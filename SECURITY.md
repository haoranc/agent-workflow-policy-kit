# Security Policy

## Scope
This repository is a documentation/template project. It does not run a production service and does not ship a runtime binary.

Security reports are still welcome, especially for:
- Secrets accidentally committed to the repository.
- Supply-chain risk in scripts or automation used by this repo.
- Unsafe guidance in templates that could cause credential leakage or harmful defaults when copied into real projects.
- Vulnerabilities in any future executable code added to this repository.

## Supported Versions

| Version | Supported |
| --- | --- |
| main (latest) | Yes |
| v0.1.x | Yes |
| Older versions | Best effort |

## Reporting a Vulnerability
Please report privately through GitHub:
- Use the repository's **Security > Advisories > Report a vulnerability** flow, if available.
- If advisories are not enabled, open a private issue with maintainers if possible, or use another private contact channel listed in the repo profile.

Please include:
- A clear description of the issue and impact.
- Reproduction steps or a minimal proof of concept.
- Affected files/paths and suggested mitigation (if known).

Do **not** post unpatched high-severity issues in public issues.

## Response Expectations
- Initial triage target: within 7 days.
- Status update target: within 14 days.
- Fix timeline depends on severity and maintainer availability.

## Disclosure
After a fix is released, responsible disclosure is appreciated. If requested, we can coordinate timing and acknowledgment in release notes.
